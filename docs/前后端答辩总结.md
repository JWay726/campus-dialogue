# 验机答辩总结 · 前端 + 后端（Spring Boot）

> 用途：学校验收/演示（验机）时老师可能提问的问题 + 可直接照讲的参考回答。
> 后端集中在 **Spring Boot** 框架相关知识点；前端集中在**原生 JS + 流式渲染**的实现细节。
> 建议按「一、整体介绍 → 二、前端 → 三、后端 → 四、深挖追问 → 五、演示话术」顺序准备。

---

## 一、整体介绍（开场 60 秒）

**一句话**：这是一个面向高校校园场景的智能对话系统，用 **Spring Boot 3.4.5（WebFlux 响应式）+ Spring Security** 做后端，
把校园资料向量化后接 **RAG 检索**，再调用**大模型（DeepSeek）**生成回答，前端是**原生 HTML/JS** 的单页应用，
支持登录、多轮会话、流式打字机效果和知识库管理。

**请求全链路（背下来，老师最爱问）**：
```
浏览器 index.html
  → app.js 用 fetch POST /api/chat（带 Cookie）
  → ChatController 校验登录、解析 sessionId
  → ChatService：
       ① 把提问写入 messages 表
       ② RetrievalService 对问题做 embedding → 在 VectorStore 里做余弦相似度检索（阈值过滤）
       ③ MemoryService 按字符预算裁剪历史
       ④ 拼 system prompt + 【校园资料】 + 历史 + 当前问题
       ⑤ LlmClient 调 DeepSeek /chat/completions（stream=true）
  → 以 SSE（text/event-stream）逐 token 推回前端
  → app.js 用 ReadableStream 边收边渲染，最后 renderMarkdown
```

**分层架构**：
| 层 | 类 | 职责 |
|---|---|---|
| 控制层 | `ChatController` / `SessionController` / `DocController` / `AuthController` | 接收 HTTP、鉴权、返回响应 |
| 业务层 | `ChatService` / `SessionService` / `RetrievalService` / `UserService` | 对话编排、会话、检索、账号 |
| 安全层 | `SecurityConfig` / `CampusUserDetailsService` / `CampusPasswordEncoder` | 登录认证、路径授权、密码校验 |
| 数据层 | `*Repository`（Spring Data JPA） | 数据库 CRUD |
| 基础设施 | `LlmClient` / `EmbeddingService` / `VectorStore` / `WebClientConfig` | 外部模型、向量库、HTTP 客户端 |

## 二、前端总结（原生 JS，无框架）

### 2.1 技术选型与文件组织

| 文件 | 作用 |
|---|---|
| `index.html` + `app.js` + `styles.css` | 聊天主页面 |
| `login.html/js`、`register.html/js` | 登录、注册 |
| `admin.html/js/css` | 知识库管理后台（ADMIN） |
| `profile.html/js` | 个人中心（学号/微信/改密） |
| `dialog.js/css` | 通用自绘对话框组件（confirm/alert/prompt/toast） |

**老师可能问：为什么不用 Vue / React？**
> 答：本项目定位是教学/毕设骨架，交互集中在单页聊天，用原生 JS 可以少一层构建工具（无需 Node/Webpack/Vite），
> 部署时直接由 Spring Boot 托管静态资源，`java -jar` 就能跑；同时能更清楚地展示 **SSE 流式解析、DOM 操作、
> XSS 防护** 这些底层原理。如果要做大型前端，再加 Vue/React 也只需替换 `static/` 目录。

### 2.2 SSE 流式接收（核心亮点）

**老师问：前端的“打字机效果”怎么实现的？**
> 答：不是 WebSocket，是 **SSE（Server-Sent Events）**。后端返回 `Content-Type: text/event-stream`，
> 前端用 `fetch` 拿到 `res.body`（一个 `ReadableStream`），再 `getReader()` 循环读取字节流：
> ```js
> const reader = res.body.getReader();
> const dec = new TextDecoder();
> // 每次 read() 拿到一段 chunk，按空行切分成一个个 SSE 事件块
> // 解析每个块的 event: / data: 两行
> if (event === 'token') { raw += data; bubble.textContent = raw; }   // 边收边显示
> if (event === 'done')  { bubble.innerHTML = renderMarkdown(raw); }  // 收完再渲染 Markdown
> ```
> 关键点：① 用 `fetch` 而不是 `EventSource`，因为 `EventSource` 只能 GET，而我们要 POST 带 JSON 请求体；
> ② 流式期间先按纯文本追加（快），**全部结束后再统一渲染 Markdown**，避免每来一个字就重新解析整段。
> ③ 用 `TextDecoder` 解码，注意一个中文字符可能被拆在两个 chunk 里，所以按事件块缓存拼接。

**追问：多个事件粘在一个包 / 一个事件被拆成两个包怎么办？**
> 答：所以不能假设「一次 read = 一个事件」。代码里维护一个 buffer，以 `\n\n` 为事件分隔符切块，
> 不完整的尾部留在 buffer 里等下一次 read 再拼（`parseSseBlock`）。

### 2.3 Markdown 渲染与 XSS 防护

**老师问：模型返回的内容直接 innerHTML，不怕 XSS 吗？**
> 答：做了防护。`renderMarkdown` 的第一步是 `escapeHtml(src)`，把 `& < > " '` 全部转义成实体，
> **然后**再在已转义的文本上做 Markdown 替换（代码块、标题、列表、粗体、行内代码）。
> 也就是「先转义、后渲染」，模型即使返回 `<script>` 也只会显示成文本。
> 另外用占位符（`@CB`/`@IC`）先替换代码块/行内代码，防止代码里的 `*`、`#` 被误当成 Markdown 语法。

### 2.4 登录态与权限（前端侧）

**老师问：前端怎么知道用户登没登录、是不是管理员？**
> 答：页面加载时调 `GET /api/auth/me`：返回 200 就带 `{username, role}`，返回 401 就跳登录页。
> 登录成功后后端会下发 **HttpOnly 的 `SESSION` Cookie**（Spring Security 的服务端会话），
> 之后所有 `fetch` 都带 `credentials: 'same-origin'`，浏览器自动携带，前端**不接触任何 token**。
> 前端根据 `role` 显示/隐藏「知识库管理」入口（`applyRole`），但**真正的权限校验在后端 Spring Security**
> （`SecurityConfig` 的 `authorizeExchange` 规则 + `@AuthenticationPrincipal`），
> 前端隐藏只是体验优化，不是安全边界——这点老师很爱追问，一定要强调「前端控制显示，后端控制访问」。

### 2.5 其他交互细节
- **会话管理**：`loadSessions` 拉列表，`selectSession` 拉历史消息，右键（`ctx-menu`）重命名/删除。
- **修改重答**：点某条用户消息进入编辑态，发新内容前先 `DELETE /api/sessions/{id}/messages?from={msgId}` 删掉该条及之后，再重新提问。
- **重新回答**：失败气泡下挂「↻ 重新回答」，先删掉错误记录，再以 `retry:true` 重发（后端不重复写用户消息）。
- **统一对话框**：所有 confirm/alert 用自研 `dialog.js`，避免浏览器原生弹窗标题显示成宿主名，且支持 `danger` 红色样式、Esc/Enter、点遮罩关闭。

## 三、后端总结（Spring Boot 重点）

### 3.1 为什么选 WebFlux？和 Spring MVC 有什么区别？

> 答：本项目核心是**流式对话**，需要把大模型的 token 一段段实时推给前端。**WebFlux 是响应式非阻塞**的，
> 底层是 Netty，用少量线程就能支撑大量并发的长连接流；而传统 Spring MVC 是 Servlet 阻塞模型，一个请求占一个线程，
> 长连接流式场景下线程容易被占满。
> 区别总结：MVC 返回普通对象 / `ResponseEntity`，WebFlux 返回 `Mono` / `Flux`；
> MVC 上传用 `MultipartFile`，WebFlux 用 `FilePart`。
> 代价是 WebFlux 要求全链路尽量非阻塞，遇到阻塞逻辑（如 JDBC、同步 HTTP）要切到 `Schedulers.boundedElastic()`。

**追问：JPA 不是阻塞的吗？在 WebFlux 里用没问题吗？**
> 答：JPA/JDBC 确实是阻塞的。所以本项目把**准备阶段的阻塞逻辑**（写库、向量化、检索）包进
> `Mono.fromCallable(...).subscribeOn(Schedulers.boundedElastic())`，切到弹性线程池执行，不阻塞 Netty 事件循环；
> 只有 LLM 的流式输出走真正的响应式 `Flux`。这是一个务实的折中——教学项目优先保证链路清晰，
> 若要彻底响应式可换 R2DBC。

### 3.2 Spring Boot 启动与自动配置

**老师问：`@SpringBootApplication` 做了什么？**
> 答：它是三个注解的组合：`@SpringBootConfiguration`（配置类）、`@EnableAutoConfiguration`（开启自动配置）、
> `@ComponentScan`（扫描启动类所在包及子包）。
> 自动配置靠 `@ConditionalOnClass` / `@ConditionalOnMissingBean` 等条件注解，只有「依赖存在且用户没自定义」时才生效，
> 这就是「约定优于配置」。比如引入了 `starter-data-jpa` 并配了数据源，它就自动装配 `DataSource`、`EntityManagerFactory`、事务管理器。

**问：启动后初始化数据怎么做的？**
> 答：用 `CommandLineRunner`（`@Bean` 返回一个 lambda）。容器启动完成后执行一次：
> `userService.seedIfEmpty()` 灌种子管理员、`documentService.seedIfEmpty()` 灌校园资料、
> 若向量库为空则 `retrievalService.indexAll()` 全量建索引。

### 3.3 配置管理

**问：配置怎么组织的？敏感信息怎么处理？**
> 答：`application.yml` 主配置 + `application-dev.yml` / `application-prod.yml` 分环境。
> 用 `@ConfigurationProperties(prefix="campus")` 把 `campus.llm.*`、`campus.rag.*` 等**成组绑定**到 `AppProperties` 对象
> （比 `@Value` 逐个注入更清晰，支持松散绑定和嵌套类）。
> 敏感项（API Key、数据库密码、签名密钥）全部写成 `${ENV:默认值}`，生产通过环境变量注入。
> 覆盖优先级：命令行 > 环境变量 > `application-{profile}.yml` > `application.yml`。

**问：开发和生产数据库怎么切换的？**
> 答：数据库**统一用 MySQL**，dev / prod 是同一套 schema。连接信息放在主 `application.yml`，
> 通过环境变量 `DB_URL / DB_USERNAME / DB_PASSWORD` 覆盖，换实例不用改代码。
> 表结构统一由 **Flyway** 管理（`db/migration/V1~V4`），启动时自动执行未应用的版本；
> Hibernate 只做 `ddl-auto: validate` 校验，不自动改表——这样本地和生产的表结构不可能出现漂移。
> 两个 Profile 的差别只剩日志、静态资源热更新这些运行细节，启动加 `--spring.profiles.active=prod` 即可切换。
>
> （早期版本为省事用 H2 文件库做开发环境，后来为了「本地与生产一致 + 迁移可追溯」已整体移除 H2。）

### 3.4 控制层（Controller）

**问：SSE 在后端怎么返回的？**
> 答：方法返回 `Flux<ServerSentEvent<String>>`，`@PostMapping(produces = MediaType.TEXT_EVENT_STREAM_VALUE)`。
> 每个事件用 `ServerSentEvent.builder().event("token").data(x).build()` 构造。
> 事件约定：`sources`（检索到的资料）→ `token`（文本增量）→ `error`（可选）→ `done`（结束）。

**问：文件上传怎么做的？WebFlux 没有 MultipartFile 吧？**
> 答：对，WebFlux 用 `@RequestPart("files") Flux<FilePart>`。用 `DataBufferUtils.join(part.content())`
> 把分块内容合并成一个 `DataBuffer`，转成 UTF-8 字符串，用完 `DataBufferUtils.release(buf)` 释放池化内存。
> 上传大小上限由 `spring.codec.max-in-memory-size: 10MB` 控制。
> （注意：Reactor 3.7.5 已移除 `Flux.aggregate()`，不能再用老写法。）

### 3.5 鉴权（Spring Security 原生登录体系）

**问：登录鉴权怎么实现的？**
> 答：用 **Spring Security 6.4 的 WebFlux 响应式安全**，走的是框架**自带的整套登录体系**，
> 没有自研过滤器、也没有自签 token。
> 1. `@EnableWebFluxSecurity` + 一个 `SecurityWebFilterChain` Bean；
> 2. **认证（表单登录）**：前端把 `username/password` 以 `application/x-www-form-urlencoded`
>    POST 到 `/api/auth/login`，由框架的 `FormLoginWebFilter` 接管，交给
>    `UserDetailsRepositoryReactiveAuthenticationManager`（响应式版 `DaoAuthenticationProvider`）：
>    - 我们只实现两个标准扩展点：
>      **`CampusUserDetailsService implements ReactiveUserDetailsService`**（查 `users` 表）
>      + **`CampusPasswordEncoder implements PasswordEncoder`**（SHA-256 + 随机盐校验，兼容存量账号）；
> 3. **登录态**：认证结果由 `WebSessionServerSecurityContextRepository` 存进**服务端 Session**，
>    下发 `SESSION` Cookie（HttpOnly），后续请求框架自动恢复 `SecurityContext`；
> 4. **登出**：`POST /api/auth/logout` 由框架 `LogoutWebFilter` 处理，清上下文 + 会话失效 + 清 Cookie；
> 5. **授权**：`authorizeExchange` 集中声明——`/api/auth/**`（除 `/me`）与登录注册页 `permitAll`；
>    `/api/admin/**`、后台页面 `hasRole("ADMIN")`；
>    `/api/chat/**`、`/api/sessions/**`、`/api/me/**`、对话页 `authenticated()`；
> 6. **取当前用户**：控制器用 `@AuthenticationPrincipal(expression = "username") String me`；
> 7. **异常响应**：自定义 `ServerAuthenticationEntryPoint` / `ServerAccessDeniedHandler`，
>    API 返回 401/403 JSON，页面 302 跳登录页/首页。
>
> 为什么用它：用户加载、密码校验、会话管理、路径授权、异常处理都是框架标准能力，
> 我们只写业务（查用户表 + 密码算法），安全细节交给框架，比手写过滤器更不容易漏配；
> 后续要加方法级权限、记住我、OAuth2 也能平滑扩展。
>
> 说明：为方便演示**关闭了 CSRF**（同源 + HttpOnly Cookie）。生产环境应开启 CSRF 并让前端携带 CSRF token。
> 会话空闲超时用 `server.reactive.session.timeout` 配置（本项目 8 小时）。

**问：越权访问怎么防的？**
> 答：两层。① 路径级：Spring Security 的 `authorizeExchange` 拦未登录/非管理员（401/403）；
> ② 数据级：会话表加了 `username` 归属列，所有会话操作都用 `findByIdAndUsername` 校验归属，
> 别的用户拿到 sessionId 也查不到、改不了（统一返回 404，不泄露是否存在）。

### 3.6 数据访问（Spring Data JPA）

**问：Repository 里没写 SQL，怎么查的？**
> 答：用 **Spring Data JPA 的派生查询**，按方法名自动生成 SQL。例如
> `findByUsernameOrderByUpdatedAtDesc` → `where username=? order by updated_at desc`；
> `findByIdAndUsername` → `where id=? and username=?`。继承 `JpaRepository` 就自带 save/findById/deleteById 等 CRUD。
> 复杂查询可以用 `@Query` 写 JPQL。

**问：事务怎么加的？**
> 答：删除会话要同时删消息和会话两条写操作，所以在 `SessionService.delete` 上加 `@Transactional`，保证原子性。
> 注意：`@Transactional` 靠 AOP 代理生效，**同类内部自调用不生效**；默认只对 `RuntimeException` 回滚。

**问：建表和迁移怎么做的？**
> 答：**统一用 Flyway**，dev 和 prod 都是同一套脚本 `db/migration/V{n}__xxx.sql`，启动时自动执行未应用的版本，
> 执行记录在 `flyway_schema_history` 表，可追溯。Hibernate 设 `ddl-auto: validate` 只做校验、不改表，
> 这样本地和生产不可能出现「结构不一致」的问题。已有非空库用 `baseline-on-migrate: true` 建基线。
> 加字段的标准流程是新增一个 `V5__xxx.sql`，而不是让 Hibernate 自动改表。

### 3.7 RAG 链路（这个必被问）

**问：什么是 RAG？你们怎么实现的？**
> 答：RAG = 检索增强生成。不让模型凭空编，而是**先查资料再回答**。四步：
> 1. **离线入库**：把校园文档切分成片段（chunk），调 bge-m3 的 `/embeddings` 得到向量，存进 `VectorStore`（内存 + 数据库持久化）。
> 2. **在线检索**：用户提问同样做 embedding，和所有片段算**余弦相似度**，取 Top-K（默认 3）。
> 3. **阈值过滤**：相似度低于 `similarity-threshold`（0.3）的片段不注入，避免答非所问。
> 4. **拼 Prompt**：把命中的资料放进 system prompt 的【校园资料】里，连同历史一起发给大模型。
> 若完全没命中，前端会提示「以下为通用回答」，而不是假装有依据。

**问：向量相似度怎么算的？**
> 答：余弦相似度 = 两向量点积 / 模长乘积，值越接近 1 越相似。项目里是纯 Java 实现的（教学目的，数据量小够用），
> 生产可换 Chroma / Milvus / pgvector 做近似最近邻（ANN）。

**问：知识库更新后怎么保证检索到新内容？**
> 答：`DocumentService` 每次新增/修改/上传文档，会先 `vectorStore.removeByDocId("doc-"+id)` **按文档去重**，
> 再重新切分索引，避免同一文档重复堆积；后台也提供「重建索引」按钮全量重建。

### 3.8 外部调用与容灾

**问：怎么调用大模型的？为什么用 WebClient？**
> 答：用 **WebClient**（WebFlux 的响应式 HTTP 客户端）调 OpenAI 兼容的 `/chat/completions`，`stream: true`，
> 把响应体 `Flux<String>` 按行解析出 `delta.content` 增量。没用 `RestTemplate` 是因为它是阻塞的，会占住事件循环线程。
> 超时必须配：`CONNECT_TIMEOUT_MILLIS`（建连）+ `responseTimeout`（等响应头），否则校园网 DNS 一抖整条链路就挂死。

**问：模型服务挂了/欠费了怎么办？**
> 答：做了**主备双通道**。主通道（DeepSeek）出现 **402 余额不足 / 429 限流 / DNS 失败 / 超时**，且**还没吐出任何 token** 时，
> 自动切换到备用通道（SiliconFlow）用同一份 prompt 重放，前端无感知。切换会打 WARN 日志。
> 另外网络类异常先在同链路重试 1 次；启动类里还关了 JDK 的 DNS 负缓存（否则一次抖动会被放大成连续 10 秒不可用）。

### 3.9 并发与限流

**问：多个用户同时问，会不会把模型服务打挂？**
> 答：会触发 429。所以用 `Semaphore` 限制同时进行的 LLM 流式调用数（`campus.llm.max-concurrent`，默认 4），
> 超出的排队等待，`doFinally` 里释放信号量。向量化那边也用固定并发度批量处理，缩短大库重建时间。

### 3.10 异常处理

**问：模型报错了前端能看到什么？**
> 答：用 `onErrorResume` 兜底，不让流直接断掉，而是下发一个 `error` 事件；并把底层异常翻译成人话
> （DNS 失败 / 超时 / 401 鉴权 / 402 余额 / 429 限流 / 其他）。如果已经输出了一部分内容，会把部分内容存库并标注「回复中断」。
> 前端据此在气泡下挂「重新回答」按钮。

### 3.11 测试

**问：写了单元测试吗？怎么测的？**
> 答：用 `spring-boot-starter-test`（JUnit 5 + Mockito），覆盖向量库、检索阈值、记忆窗口、鉴权、**会话隔离**等。
> 用 `@Mock` 造仓储、`@InjectMocks` 注入被测服务，`when/verify` 打桩和校验。
> 有个坑：JDK 17+ 模块系统默认禁止 Mockito 改写字节码，所以 surefire 配了 `--add-opens java.base/java.lang=ALL-UNNAMED` 等。

## 四、老师可能深挖的追问（准备好这几条）

**Q1：为什么不用数据库存向量，而是内存 + 数据库？**
> 内存里存一份用于快速余弦计算，数据库存一份用于重启后恢复（`loadFromDb`）。教学项目数据量小，这样最简单；
> 数据量大应上专业向量库，用 ANN 索引。

**Q2：上下文字符预算是什么？为什么要做？**
> 大模型有上下文窗口上限。`MemoryService` 不从「最近 N 条」硬截，而是**从最近一条往前累加字符**，
> 累计到 `max-chars`（4000）就停，保证既保留最新对话、又不超模型上限。

**Q3：会话隔离后，旧数据怎么办？**
> 升级前的老会话没有 `username`，升级后是 NULL，变成「无人可见」的孤儿数据——这是有意的，因为无法判断归属。
> 新会话创建时就写入当前登录用户。

**Q4：前端怎么防重复提交 / 断流？**
> 发送时禁用按钮，`finally` 里恢复；流结束（done 或 error）才允许再次发送。失败气泡提供「重新回答」，
> 重发前先删掉错误记录，避免会话里出现重复问答。

**Q5：为什么用 Cookie（Session）而不是把 token 存 localStorage？**
> 登录态存在服务端 Session 里，浏览器只持有一个 HttpOnly 的 `SESSION` Cookie：
> 前端 JS 读不到（降低 XSS 窃取风险），浏览器同源请求自动携带（省去手动加 Header），
> 而且服务端可以随时让会话失效（登出、改密），比自签无状态 token 更可控。

**Q6：项目怎么部署？**
> `mvn package` 打出可执行 fat jar，`java -jar` 运行；也提供了 `Dockerfile`（`eclipse-temurin-25` 基础镜像）。
> 数据库统一 MySQL，用 `--spring.profiles.active=prod` 切到生产 Profile（关闭 SQL 日志等），
> 连接与凭据全部通过 `DB_URL / DB_USERNAME / DB_PASSWORD` 环境变量注入，表结构由 Flyway 启动时自动迁移。

## 六、常见翻车点与应对（老师问「遇到过什么问题」时用）

| 现象 | 根因 | 怎么解决/怎么讲 |
|---|---|---|
| 问了没答复 / DNS 报错 | 实际是 DeepSeek 欠费 402，被 DNS 误判掩盖 | 加 402 文案分支 + 主备双通道，直连验证 HTTP 402 |
| Java 改完不生效 | 用的 `java -jar` 跑的是打包快照 | dev 用 devtools 热重启 + 静态资源直读源码；改 Java 需重新打包 |
| 上传接口 500 | Reactor 3.7.5 删了 `Flux.aggregate()` | 改 `DataBufferUtils.join()` |
| 单测在 JDK 25 报 Mockito 错 | 模块系统禁止改写字节码 | surefire 加 `--add-opens`；具体类改用 fake 子类 |
| 个人中心未绑定却显示「解绑」 | CSS `.row{display:flex}` 覆盖了 `[hidden]` | 加 `[hidden]{display:none!important}` 兜底 |
| 弹窗标题显示成宿主名 | 用了原生 `confirm/alert` | 抽 `dialog.js` 自绘对话框 |
| 用户聊天记录串台 | 会话表无归属字段 | 加 `username` 列 + 全链路归属校验（越权 404） |
| 迁移 Spring Security 后越权页面返回 200 只带 Location | `AccessDeniedHandler` 里只 `setStatusCode` + `setComplete()`，状态码未提交 | 改为显式写入空 body（`writeWith` 空 `DataBuffer`）强制提交 302 |
| 未登录 API 被重定向到登录页而非 401 | 入口点未区分页面/API | `ServerAuthenticationEntryPoint` 里按 `/api/` 前缀返回 JSON 401，否则 302 |
| `@AuthenticationPrincipal` 注入为 null | 路径未声明 `authenticated()`；或 principal 类型不是 `UserDetails`（如手动存成 String） | 检查 `authorizeExchange` 规则；手动建 Authentication 时 principal 用 `User.withUsername(...).build()` |
| 前端登录一直 401/参数收不到 | `formLogin` 只认 `x-www-form-urlencoded`，仍用 JSON 提交 | `body: new URLSearchParams({username, password})` |
| 微信登录后 `/api/me` 401、`/api/sessions` 500 | principal 存成 String，SpEL `expression="username"` 取不到属性 | 统一 principal 为 `UserDetails` |
| WebFlux 里 `loginProcessingUrl()` 编译报错 | 该方法只有 Servlet 版 `FormLoginSpec` 有 | 改用 `requiresAuthenticationMatcher(pathMatchers(POST, "/api/auth/login"))` |
